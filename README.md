# 心动计划局｜Date Box

为两个人生成一场带有惊喜、任务和回忆的约会计划。

Date Box 是一款双人约会互动游戏，既可以共用一台设备完成，也可以由一方生成邀请链接、另一方异步回答后把结果发回。两份期待会生成包含路线、隐藏任务与临时彩蛋的共同计划，最后收进纪念回忆卡。

## 当前版本

当前正式版本为 **Date Box v1.1.0**：同时支持单设备模式与无数据库异步邀请模式。异步邀请已形成“创建邀请 → TA答题 → 结果回传 → 邀请人查看共同计划”的纯前端闭环。

## 项目背景

很多约会灵感工具只给出地点清单，选择成本依然留给用户；常见默契测试又容易停留在“答题—得分”，没有把结果转化为能共同完成的体验。Date Box 将偏好表达、双人默契、计划揭晓、现场任务和事后纪念串成一条完整流程。

## 用户痛点

- 想约会却不想在大量选项中反复讨论。
- 希望了解彼此期待，又不想面对正式问卷的压力。
- 计划往往只有行程，没有能制造共同记忆的互动。
- 一次约会结束后，缺少轻量且适合保存的纪念载体。

## 产品目标

- 在三秒内说明产品用途，并让两个人自然开始共同选择。
- 用轻游戏方式汇合两个人的偏好，不把低默契描述成失败。
- 生成容易扫描、可以直接执行的约会路线与任务。
- 用可截图的纪念票据收束体验，并在单设备上可靠恢复进度。

## 两种使用模式

### 一起用这部手机

适合两个人在同一地点，轮流使用同一设备完成问答。

1. 阅读玩法并开启计划。
2. 选择当下心情与约会条件。
3. 玩家 A 完成五题，交接设备后由玩家 B 完成五题。
4. 查看默契结果与共同、互补期待。
5. 长按开启盲盒，揭晓约会计划。
6. 更换或保存计划，开始约会并完成、跳过任务或触发彩蛋。
7. 填写最喜欢的瞬间与想对 TA 说的话，保存或复制纪念文字。
8. 刷新后恢复本地进度，或确认重新开始并清空数据。

### 邀请TA一起计划

玩家 A 创建邀请链接，玩家 B 在另一台设备中完成答题，最后揭晓共同结果。

1. 玩家 A 填写可选称呼，选择心情、时间、预算、距离、关系阶段并完成五题。
2. 浏览器生成带 `#invite=v1.*` 的邀请链接和 48 小时有效的 3:4 邀请卡/二维码。
3. 玩家 B 在另一台设备打开链接，只回答五道默契问题；完成前看不到玩家 A 的答案。
4. 两份答案经过双轨汇合动效后显示默契、共同期待与互补期待，并生成推荐计划。
5. 玩家 B 可复制或系统分享 `#result=v1.*` 结果链接，也可发送 3:4 结果截图卡。
6. 玩家 A 打开结果链接后，页面用本地纯函数重新计算默契和推荐计划，显示路线与隐藏任务。

异步模式没有实时房间、登录或云端同步；双方通过 URL Hash 在设备之间传递经过校验的静态数据。

## 当前核心功能

- 六种心情与时间、预算、场景偏好选择。
- 双人分段默契问答、设备交接与结果汇合。
- 长按盲盒、提前松开取消和清晰的开启进度。
- 基于双方选择生成计划，支持有限次数的换一换。
- 路线、常规任务、隐藏任务和临时彩蛋进度管理。
- 实时回忆卡预览、保存、复制与 Clipboard 降级提示。
- 版本化 localStorage 自动保存、损坏数据恢复与重新开始确认。
- 键盘操作、焦点管理和 `prefers-reduced-motion` 支持。
- 48 小时异步邀请、邀请/结果链接编解码、跨邀请会话隔离和刷新恢复。
- 邀请卡二维码、结果截图卡、Clipboard/Web Share 与微信内手动复制降级。
- 玩家 A 创建邀请、玩家 B 独立答题、双人默契结果揭晓与手动结果回传。
- 微信内置浏览器适配与 CloudBase 国内静态部署。

## 手机端与微信浏览器体验

- Mobile-first 布局，主流程针对单手操作、动态视口和安全区域优化。
- Welcome、心情选择、默契结果、盲盒、路线与回忆卡均有独立移动端信息层级。
- 已适配微信内置浏览器的安全区域、触控长按、文本输入与静态资源加载场景。
- 生产链接可在微信中直接打开；进度仍仅保存在当前浏览器的本地存储中。

## 设计理念

视觉以奶油底色、克制的粉紫、双轨迹汇合和纪念票据为核心。玻璃质感只用于需要层次的区域，不把所有内容做成相同白色卡片；按钮、信息层级和动效在整条流程中保持一致。文案使用性别中立的“TA、你们、对方”，默契差异被表达为互补期待或新的探索方向。

## 静态构建

项目已配置为 Next.js 纯静态导出。执行：

```bash
npm run build
```

构建完成后，站点文件位于项目根目录的 `out/`：

- `out/index.html` 是首页入口。
- `out/_next/` 包含带哈希的 JavaScript、CSS 与其他构建资源。
- `out/icon.svg`、`out/404.html` 等文件可直接交给静态网站托管平台。

本地必须用静态服务器验证 `out/`，不要用 `next dev` 代替：

```bash
npx serve out -l 4173
```

打开 `http://localhost:4173`。启用 `trailingSlash` 后，托管平台应保留目录式路径与其中的 `index.html`。

## CloudBase 静态托管部署

当前稳定版已部署到 CloudBase 国内静态托管。每次发布按以下流程执行：

1. 在本地运行 `npm run build`，生成 `out/`。
2. 将完整 `out/` 目录内的全部内容上传到 CloudBase 静态网站根目录，确保 `index.html` 直接位于托管根目录。
3. 保持默认首页为 `index.html`、错误页为 `404.html`，并保留目录式路由下的 `index.html`。
4. 在 HTTPS 部署链接与微信内置浏览器中走通单设备模式、邀请链接和结果链接。
5. 每次代码更新后重新执行 build 并重新上传完整 `out/`；可在部署地址后附加查询参数（例如 `?v=1.1.0`）确认新版缓存，查询参数不会改变 Hash 数据。

CloudBase 需要重新上传的是构建后的 **`out/` 目录内全部内容**，不是源码目录，也不要只上传发生变化的文件。Hash 位于 `#` 之后，不会发给静态服务器，因此 CloudBase 只需正常返回同一个 `index.html`。

仓库不保存 CloudBase 项目 ID、访问令牌、上传凭据或任何私有部署参数。

## 静态版本限制

- 站点没有运行时 Next.js 服务器，不能使用 Server Actions、依赖请求参数的 Route Handler、cookies、headers、middleware/proxy、服务端重定向或 rewrite、ISR 与默认图片优化服务。
- 计划、问题与任务均随构建产物发布；内容变化需要重新执行 `npm run build` 并部署新的 `out/`。
- 单设备进度和每份邀请的本地进度保存在当前浏览器的 localStorage；清理站点数据会丢失本机恢复能力，但已经发出的链接仍包含创建时的数据。
- Clipboard 能力受浏览器权限和安全上下文影响，生产环境应使用 HTTPS；不可用时应用会提供手动复制降级。
- 当前应用是单页面客户端状态机，不提供数据库、服务端 API、登录、云同步或动态服务端路由。

## 无数据库工作原理

- 题目、计划和算法随静态 JavaScript 一起发布。
- 使用 URL Hash 传递邀请和结果数据，并采用 JSON、UTF-8 与 Base64 URL-safe 编码；浏览器只在客户端解析。
- 玩家 A 的偏好与五道答案编码在邀请 Hash；玩家 B 的五道答案和计划 ID 编码在结果 Hash，不依赖数据库或后端接口。
- Hash 不会包含在浏览器对服务器的 HTTP 请求中，但拿到完整链接的人可以在本地解码其中内容；它不是加密或访问控制。
- 页面入口先校验版本、字段、时间、邀请 ID、答案 ID、偏好 ID 和计划 ID，再进入流程。
- 玩家 A 的结果页重新调用 `calculateCompatibility` 和 `generateDatePlan`，不会信任链接携带的展示文案或分数。
- 本地进度保存在 localStorage；玩家 B 会话按 `inviteId` 隔离，多个邀请不会互相覆盖。
- 邀请默认 48 小时有效；纯静态版本无法主动撤回已发出的邀请，重新生成也不会让旧链接立即失效。

## URL Hash 与隐私限制

- 邀请协议：`#invite=v1.<base64url-json>`；结果协议：`#result=v1.<base64url-json>`。
- 玩家 B 完成五题前，界面不展示玩家 A 的具体答案、心情、默契预测或推荐计划。
- 结果卡只展示称呼、默契度、关键词、计划名和纪念文案，不列出完整答案表。
- 不要在称呼中填写手机号、微信号、地址或其他敏感信息；任何拿到链接的人都可能读取其中数据。
- Date Box 不要求注册，也不主动收集手机号或微信号。链接持有者可能读取其中的编码内容，请谨慎转发邀请和结果链接。
- 邀请默认在创建后 48 小时失效；过期、损坏或版本不支持的链接不能进入答题流程。

## 当前版本范围

Date Box v1.1.0 是支持完整单设备流程，以及纯 Hash 异步邀请、结果回传、邀请/结果截图卡、本地恢复和边界保护的正式版本。所有计划内容来自仓库内静态数据，不依赖远程服务。

## 已知限制

- 不支持实时在线状态、邀请撤回或多设备自动同步。
- 结果需要玩家 B 手动分享回玩家 A。
- 数据主要存在链接和当前浏览器的 localStorage 中；清除浏览器数据可能导致本地进度丢失。
- 计划与任务为本地静态内容，不包含地图导航、营业时间或实时地点信息。
- Web Share 和 Clipboard 能力取决于浏览器权限与安全上下文；不可用时使用页面提供的手动复制方式。
