# 心动计划局 Date Box — 产品规格

## Invite Stage 1：异步邀请入口协议

异步邀请 v1.1.0 的第一阶段只建立静态链接协议和入口识别，不包含正式的邀请创建、对方答题或结果展示页面。普通单设备流程继续完整运行，且继续使用 `date-box-game-state-v1` 保存进度；异步会话预留独立键 `date-box-async-session-v1`，两类进度不得互相覆盖。

- 邀请 Hash：`#invite=v1.<encodedPayload>`；结果 Hash：`#result=v1.<encodedPayload>`。
- payload 使用 JSON、UTF-8 与 Base64 URL-safe 编码，可安全包含中文昵称；链接生成前移除当前 URL 的原有 Hash。
- 邀请默认有效期为 48 小时；双方称呼均可选，填写时最多 12 个字符。
- 邀请人和对方答案都必须刚好包含五项，并逐题使用 `src/data/quiz-questions.ts` 中已有的合法选项 ID。
- 偏好必须使用现有 mood、time、budget、distance 与 relationship ID；结果计划必须使用 `src/data/date-plans.ts` 中已有的计划 ID。
- 页面挂载后识别 Hash。无 Hash 或无关 Hash 进入现有普通模式；有效邀请、有效结果、过期数据和无效数据分别进入清晰占位状态。
- Base64、JSON、版本、字段、ID 或时间校验失败的数据不得进入游戏状态机，页面只显示用户可理解的错误信息，不显示技术堆栈。

本阶段不新增认证、数据库、API、实时房间或正式异步玩家页面。

## Invite Stage 2：玩家 A 创建邀请

普通 Welcome 页面提供两种主次明确的入口：视觉主入口“邀请TA一起计划”进入跨设备异步创建，次入口“一起用这部手机”继续现有完整单设备流程。移动端两张入口卡纵向排列，桌面端可并排展示。

玩家 A 创建流程固定为：

```text
create-intro → mood → preferences → host-quiz → generating → share-placeholder
```

- 双方称呼均可选，输入前后空格会被移除，每项最多 12 个字符；页面明确提示不要填写手机号、微信号或其他敏感信息。
- 心情、时间、预算、行动范围、关系阶段和五道问答复用现有合法 ID 与选择组件；玩家 A 的答案在 TA 完成前不展示。
- 生成时优先使用 `crypto.randomUUID()`，不支持时使用 `crypto.getRandomValues()` 生成 UUID v4；创建时间使用当前时间，默认 48 小时失效。
- 完成后调用 `createInviteUrl`，将邀请链接、创建时间、当前步骤、称呼、偏好和玩家 A 答案保存在 `date-box-async-session-v1`。
- 刷新后恢复尚未完成的创建步骤或分享占位；普通模式 `date-box-game-state-v1` 不被读取、覆盖或清除。
- Stage 2 只提供生成中与分享页占位，不包含正式分享卡、复制/系统分享能力或玩家 B 页面。

## 1. 产品定位

心动计划局 Date Box 是一款同设备、双人轮流参与的约会计划互动游戏。它通过心情与条件选择、五道默契问答、温和的结果反馈和长按开盒仪式，为两个人生成一套现实可执行的本地约会计划。

产品标语：**把普通的一天，变成两个人的小小冒险。**

产品使用中始终采用中性称呼“TA、你们、对方”。默契度低只代表选择更互补，不描述为失败、不合适或不匹配。

## 2. 用户场景

- 两个人在见面后临时决定“今天做什么”，共用同一台手机完成流程。
- 第一次约会需要一条安全、低压力、可提前结束的路线。
- 稳定关系中的两个人想打破重复日常，用任务和彩蛋增加新鲜感。
- 预算、时间或出行范围有限，希望快速得到可执行方案。
- 完成约会后，两个人用文字生成一张可保存的回忆卡。

## 3. 完整流程

```text
欢迎页
→ 心情选择
→ 约会条件设置
→ 玩家 A 默契问答
→ 手机交接
→ 玩家 B 默契问答
→ 默契结果
→ 长按开启约会盲盒
→ 约会计划结果
→ 约会任务模式
→ 回忆卡
```

流程必须支持刷新恢复、重新开始和在当前设备继续。玩家 B 回答前不得看到玩家 A 的答案。

## 4. 页面状态

| `GameStep` | 页面职责 | 主要动作 |
| --- | --- | --- |
| `welcome` | 品牌欢迎与流程说明 | 开始计划 |
| `mood` | 选择今晚心情 | 单选、下一步 |
| `preferences` | 设置时间、预算、范围、关系阶段 | 四组单选、确认 |
| `player-a-quiz` | 玩家 A 完成五题 | 作答、提交 |
| `handoff` | 隐藏答案并提示交接手机 | 确认已交给 TA |
| `player-b-quiz` | 玩家 B 完成五题 | 作答、提交 |
| `compatibility` | 展示默契度、共同点和互补点 | 查看结果、继续 |
| `mystery-box` | 长按开启计划 | 长按、键盘等价操作 |
| `plan` | 展示路线与隐藏任务 | 接受计划、最多更换三次 |
| `active-date` | 按顺序完成四个路线步骤 | 完成、跳过、临时彩蛋 |
| `memory` | 填写最喜欢的瞬间与留言 | 生成回忆卡、重新开始 |

## 5. 功能范围

### MVP 内

品牌首页、心情与约会条件选择、双人轮流问答、默契度与洞察、长按盲盒、本地计划匹配、六套计划、计划更换、任务模式、八个临时彩蛋、回忆卡、`localStorage` 保存与恢复、重新开始、移动端与桌面端响应式、README、lint 与构建检查。

### MVP 外

登录注册、数据库、远程 API、真实联网房间、AI、地图和商家接口、支付、后台、服务端照片上传、复杂 3D、Canvas 粒子系统。

## 6. 五道默契问答

1. 今天更想把时间花在哪里？吃点好吃的 / 随便走走 / 一起体验新鲜事 / 找地方坐下聊天。
2. 今晚更想留下什么？一张好看的照片 / 一段认真聊天的时间 / 一个很好笑的瞬间 / 一件小小纪念品。
3. 你更期待哪一种惊喜？对方准备的小礼物 / 突然出现的隐藏地点 / 一句没有说过的话 / 完全随机的安排。
4. 你希望今晚是什么节奏？慢慢来 / 紧凑一点更充实 / 一半计划一半随缘 / 完全跟着感觉走。
5. 今天最想从对方那里得到什么？陪伴 / 理解 / 新鲜感 / 浪漫回应。

程序只使用 `src/data/quiz-questions.ts` 中的稳定英文 ID 判断，中文仅用于展示。

## 7. 六套约会计划

| 计划 | 核心体验 | 典型适用 |
| --- | --- | --- |
| 晚风散步计划 | 饮品、明亮路线、停留聊天、声音明信片 | 治愈、浪漫、想聊天 |
| 粉色电影夜 | 共同选片、交换零食、观影、散场短聊 | 浪漫、雨天、低压力 |
| 未知街区探险 | 安全边界、轮流带路、发现街区 | 冒险、新鲜感、较远范围 |
| 快乐能量补给站 | 轻游戏、食物补给、胜利散步 | 玩乐、回血、轻运动 |
| 第一次靠近 | 公共地标、共同选择、轻问答、可选散步 | 初次约会、暧昧阶段 |
| 二十元浪漫实验 | 限额小物、共享点心、手写纪念 | 低预算、创意、仪式感 |

每套计划固定包含四个现实路线步骤、一个隐藏任务和一句结束语；不出现真实商家名称。

## 8. 默契计算

- 五题逐题比较稳定选项 ID；`rawScore = Math.round((matchedCount / 5) × 100)`。
- 展示分使用固定、可复现的温和档位：0 题相同为 52，1 题为 56，2 题为 62，3 题为 74，4 题为 88，5 题为 96；永不显示 100 分。
- `matchedCount` 用于生成共同期待；不同答案按题目语义生成互补期待，不使用“不匹配”“失败”等负面词。
- 80 分以上强调几乎相同的期待，60–79 分强调相似与惊喜并存，低于 60 分强调不同期待可以拼成完整体验。
- 结果页至少展示一条共同期待、一条互补期待和一条由双方实际选项生成的计划建议；全相同时用互补分工替代虚构分歧。

## 9. 计划匹配规则

每套计划按稳定规则累计匹配分：心情 4、时间 2、预算 2、距离 1、关系阶段 3。双方都选择聊天、新鲜体验、照片或礼物相关选项时，分别为对应类型计划增加 1–2 分；双方差异达到四题以上时，多类型活动计划增加 2 分。

第一次约会时，“第一次靠近”额外增加 3 分，优先保证公开场所、清晰返程和可提前结束。预算为 `simple` 时，对粉色电影夜、快乐能量补给站等较高消费路线扣减 9 分，避免只因心情相符而优先推荐。

计划按得分降序排列；同分时使用偏好、双方答案和计划 ID 生成的稳定 seed 排序，因此刷新不会改变结果。更换计划时排除 `seenPlanIds`，最多更换三次。所有计划都看过时回到最高分计划并显示已看完提示；达到更换上限后保留当前计划。

## 10. 状态数据结构

主状态 `DateGameState` 包含：当前步骤、五项偏好、双方答案、默契结果、当前计划 ID、已看计划、换计划次数、已完成/跳过步骤、最喜欢的瞬间、给对方的话、更新时间。

类型定义以 `src/types/date-game.ts` 为唯一来源。默认状态从 `welcome` 开始，所有选择为空、数组为空、计数为 0，时间戳在创建状态时生成。

## 11. 本地保存

- localStorage 键名固定为：`date-box-game-state-v1`。
- 持久化内容使用带版本号的纯 JSON 结构；当前版本为 `1`，只保存 `DateGameState` 数据，不保存函数或 React 节点。
- 只在客户端挂载后读取与写入，禁止模块作用域访问 `window` 或 `localStorage`。
- 每次关键选择、提交问答、切换步骤和更新回忆时保存，并更新 `updatedAt`。
- 解析失败、版本不兼容或字段缺失时回退到默认状态；不得让损坏数据阻塞页面。
- “重新开始”先二次确认，再清除该键并恢复默认状态。

## 12. 核心页面文案

- 品牌：Date Box / 心动计划局。
- 标语：把普通的一天，变成两个人的小小冒险。
- 开始按钮：开启今晚的小冒险。
- 交接提示：接下来交给 TA。放心，刚才的答案已经藏好了。
- 默契结果引导：相同的选择让你们同频，不同的选择让今晚更有惊喜。
- 盲盒按钮：长按开启心动盲盒。
- 计划更换：换一种今晚。
- 任务模式：出发，开始约会。
- 回忆卡标题：今晚，被你们好好收藏了。
- 空状态：先做一个选择，今晚的线索就会慢慢出现。

## 13. 异常与边界情况

- 未完成必填选择不能进入下一步，错误提示贴近对应选项组。
- 快速重复点击或长按只触发一次步骤切换。
- 页面隐藏、指针移出、触摸取消或按键松开时取消长按进度。
- localStorage 不可用时允许继续游戏，只提示本次无法自动恢复。
- 恢复状态指向不存在的计划或步骤时，修正到最近的合法状态。
- 刷新时避免先显示默认页再跳转造成闪烁；读取完成前使用轻量加载状态。
- 文案过长、系统字体放大和 320px 宽度下不得产生横向溢出。
- 用户跳过任务时保留可继续路径，不施加负面评价。

## 14. 优先级

### P0 — 必须完成

完整主流程、五道问答、默契计算、六套计划、本地匹配、长按开盒、任务模式、回忆卡、保存恢复、重新开始、响应式、可访问焦点、lint/build 通过。

### P1 — 应该完成

更换计划、临时彩蛋、共同点与互补点的多样文案、步骤跳过、恢复提示、减少动态效果适配、桌面专属构图。

### P2 — 有余力再做

回忆卡导出图片、更多本地计划、分享文案、细微音效开关、增强的入场动效。P2 不得影响三小时内完成 P0。
